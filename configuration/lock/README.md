# Screen Lock

What runs when the screen locks: on `mod+Home`, on the `XF86ScreenSaver` key, after the X
idle timer, when systemd asks for a session lock, and before every suspend.

The locker is [xsecurelock](https://github.com/google/xsecurelock), chosen because it fails
closed. If it cannot take over the screen it refuses to exit, rather than returning quietly
and leaving an unlocked desktop behind — which is the one way a lock screen can fail that
matters.

## What Is Here

| File | |
|---|---|
| `lock.sh` | sources the environment and execs the locker. Holds no appearance of its own |
| `environment` | generated by `helper/patch_lock.py` from the active palette; gitignored |

`lock.sh` uses `exec` rather than running the locker as a child, because `xss-lock` watches
that process to know whether the screen is still locked. A wrapper outliving the locker would
leave it believing the screen was covered when it was not.

## What It Shows

The colours and font come from the palette, so the lock screen changes with the theme like
everything else. What it *withholds* is a deliberate choice made in `helper/patch_lock.py`:
the username, the hostname and the date are all off, and the password field reveals neither
its length nor that anything is being typed.

A lock screen is read by whoever walks past it, and that is the one audience you are not
there to challenge. Everything it displays is offered to them.

## What Triggers It

`~/.xinitrc` starts `xss-lock`, which watches three things: the X idle timer (set by the
`xset s` line above it), `loginctl lock-session`, and systemd's suspend. It runs with
`--transfer-sleep-lock`, which holds the sleep inhibitor until the locker is actually up — so
the machine cannot suspend into a state where it wakes unlocked.

## Changing It

Edit `helper/patch_lock.py`, then:

```bash
python helper/patch_lock.py
```

A setting that is not palette-derived goes in that script's `BEHAVIOUR` table, so it survives
regeneration. Editing `environment` by hand lasts until the next theme switch.
