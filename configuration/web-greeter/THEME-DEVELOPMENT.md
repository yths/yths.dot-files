# Web-Greeter Theme Development

How to author a new web-greeter theme that integrates with the palette-patching pipeline. For installation and patching workflow, see [README.md](README.md); for the preview tooling, see [preview/README.md](preview/README.md).

## Required Files

A theme is a directory under `configuration/web-greeter/themes/<name>/`. The minimum file set:

```text
configuration/web-greeter/themes/<name>/
  index.html        # entry point loaded by web-greeter
  style.css         # static styles
  theme.css         # generated by helper/patch_web_greeter.py (do not edit by hand)
  theme.json        # contract with the patcher (role_map, layout, symbols, strings, ...)
  index.yml         # web-greeter metadata (theme name, primary HTML file)
```

Themes whose directory name starts with `_` (e.g. `_shared`) are treated as shared-asset directories: the patcher skips them, and their contents are copied into every other theme during deployment so installed themes under `/usr/share/web-greeter/themes/` remain self-contained.

## `theme.json` Schema

The contract between the theme and `helper/patch_web_greeter.py`:

```json
{
  "wallpaper_key": "dark",
  "role_map": {
    "background": "background",
    "foreground": "foreground",
    "highlight": "highlight",
    "failure": "failure",
    "success": "success",
    "notification": "notification",
    "warning": "warning"
  },
  "layout": {
    "status_bar": "top-right",
    "input_bar": "center",
    "message_bar": "bottom"
  },
  "font_overrides": {},
  "symbols": {
    "user_prompt":     "",
    "password_prompt": ""
  },
  "strings": {
    "welcome":      "welcome",
    "auth_failed":  "authentication failed"
  }
}
```

| Field | Role |
|---|---|
| `wallpaper_key` | Which key under `configuration.wallpapers` the theme uses as its background (e.g. `"dark"`, `"light-highlight"`). |
| `role_map` | Maps the theme's internal role names (left) to palette tokens (right). The patcher generates `--<role>: <hex>` CSS variables. |
| `layout` | Free-form layout hints the theme's own CSS/JS consumes. The patcher does not interpret these. |
| `font_overrides` | Per-theme overrides on top of `configuration.font` (e.g. `{"family": "monospace"}`). |
| `symbols` | Glyph strings the theme injects via `[data-symbol="<key>"]` selectors. |
| `strings` | Localised user-facing strings injected via `[data-string="<key>"]` selectors. |

Add a role under `role_map` whenever the theme needs a new colour-bound CSS variable. Reach for semantic palette tokens (`positive`, `negative`, `neutral`, `effect_*`) from [../../docs/palette-semantics.md](../../docs/palette-semantics.md), not raw hue names — themes that hardcode `red` or `blue` will not survive a palette redesign.

## CSS Variables Contract

`helper/patch_web_greeter.py` emits `theme.css` containing one CSS variable per role, plus the font family:

```css
:root {
  --background: #ebebeb;
  --foreground: #787878;
  --highlight:  ...;
  --failure:    ...;
  --success:    ...;
  --notification: ...;
  --warning:    ...;
  --font-family: "Iosevka NF";
}
```

The theme's static `style.css` references these variables; the generated `theme.css` is the only file that changes when the palette or active light/dark variant changes. Treat `theme.css` as build output — never edit it directly.

## Iterating

The preview server lets you exercise the theme in a regular browser with mocked `window.lightdm` and live `theme.json` editing. Start it from the repo root:

```bash
python configuration/web-greeter/preview/server.py
xdg-open http://127.0.0.1:8765/
```

The 17-step verification checklist in [preview/README.md](preview/README.md) covers the panels and interactions a theme must support. Run through it once before deploying.

## Deploying

```bash
sudo cp -RL configuration/web-greeter/themes/<name> /usr/share/web-greeter/themes/<name>
```

Set the active theme in `/etc/lightdm/web-greeter.yml`. After any palette change in `~/.config/config.json`, rerun `python helper/patch_web_greeter.py` so the installed theme's `theme.css` is regenerated; then redeploy.
