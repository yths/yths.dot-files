# Dependencies

What this desktop needs installed, and which Arch package provides it. The only blessed
install path is `yay -S`, from the `[packages]` groups in [../setup.toml](../setup.toml);
[install.md](install.md) carries the command and the order of the steps around it.

## Python Imports

Which files import what is derived from the code, so this table cannot drift from it. The
Arch package name is the part nothing in the source can tell you — `import PIL` comes from
`python-pillow` — so that mapping is hand-maintained, in `ARCH_PACKAGES` in
[../helper/list_dependencies.py](../helper/list_dependencies.py).

`python helper/gendocs.py --check` fails if an import has no package recorded, or a
recorded package is no longer imported. Adding a dependency therefore means adding one
entry there and running `python helper/gendocs.py`; nothing else needs editing.

There is deliberately no `[project]` table in `pyproject.toml` and no `requirements.txt`:
nothing installs this repository as a package, so packaging metadata would describe an
install path that does not exist. `pyproject.toml` holds tool configuration only.

## System Packages

Not derivable — these are services, runtimes and fonts, not imports. The list `./bootstrap.sh`
installs is in [../setup.toml](../setup.toml) under `[packages]`, grouped by what stops
working without them; this table says what each group's less obvious members are for.

| Arch package | Role |
|---|---|
| `valkey` | Redis-compatible server; the backend service publishes to it and the bar reads from it |
| `xorg-server`, `xorg-xinit` | X11 |
| `qtile` | window manager (also provides `libqtile`) |
| `ttf-iosevka-nerd` | `Iosevka NF`, the fallback font `[desktop] fallback_font_package` names in `setup.toml`. The theme's own font is installed from the bundle's `font.family` through `FONT_PACKAGES` in [../helper/fonts.py](../helper/fonts.py), and is not in `[packages]` at all |
| `lightdm` | login screen |
| `nody-greeter` | the web-greeter runtime LightDM renders the login screen with. Not a `[packages]` entry: `./bootstrap.sh` builds it from [../packages/nody-greeter/](../packages/nody-greeter/), since the AUR package no longer builds |
| `python-colour-science`, `openimageio` | perceptual colour matching, and the image library `colour` imports when it is present. Also built from [../packages/](../packages/README.md): the AUR PKGBUILD leaves `openimageio` out of `depends` and has a test that fails against the current one |
| `plymouth` | boot splash |
| `pacman-contrib`, `yay` | required by the backend service's pacman post-transaction hook |
| `displaycal` | **optional** — provides `dispwin`, which `~/.xinitrc` uses to load display colour profiles. Without it the desktop runs uncalibrated and nothing fails |

## Checking a Machine

`python helper/list_dependencies.py --missing` lists every recorded import the current
`python` cannot find, each with the package that provides it, and exits 1 if there are any.
`./bootstrap.sh` runs it between installing the packages and running `install.py`, because
a package installed for `/usr/bin/python` is invisible to a virtualenv or `pyenv` shim that
happens to be first on `PATH` -- and without the check that arrived as an `ImportError` from
inside `helper/patch_configurations.py`.

## Removing a Dependency

Delete the import, delete its `ARCH_PACKAGES` entry, run `python helper/gendocs.py`, and
prune the package from `[packages]` in [../setup.toml](../setup.toml). The check will tell
you if you do only some of those.
