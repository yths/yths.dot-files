# Palette Reference

Everything a theme sets, and every field that carries it — both directions, plus the tools
that still hardcode hex instead. The block below is generated by
[`helper/list_palette.py`](../helper/list_palette.py) — run `python helper/gendocs.py` to
refresh it.

> Three documents cover the palette, and they answer different questions. **What a token
> means** is [palette-semantics.md](palette-semantics.md). **What it looks like** in each
> preset is [palettes/](palettes/). **Where it is used** is this file.

A theme sets three kinds of value — the palette's tokens, the font, and the wallpapers — so
this covers the two beside the palette as well, in a file named for the palette. They arrive
by the same route and answering "where does this go?" for one and not the others would send
the reader back to the source for half the question.

It has four parts:

- **Palette** — the semantic `token → hex` table, read from the active `~/.config/config.json`.
- **Theme value → usage** — for each value a theme sets, every field that carries it, in which
  file, and what happened to it on the way. Answers *if I change `highlight`, what moves?*
- **Configuration file → theme values** — the same records keyed by file. Answers *where did
  this value in my dunstrc come from?*
- **vscode** and the **drift report** — the two mappings that are resolved rather than
  declared. VSCode's every colour is matched perceptually against the palette; the drift
  report reverse-maps hex hardcoded *outside* the palette (kitty, tmux, starship, dunst,
  rofi), where an `exact` ΔE means the hardcoded value still matches a token.

The usage map is recovered by reading the patcher sources with `ast` rather than by running
them, which is what lets it render on a clone with no install. Two consumers diverge from
what a static reading would say, so both are recorded explicitly rather than inferred:
web-greeter's font size is **pinned** by its `theme.json#font_overrides`, and plymouth always
renders the **dark** variant whatever `state.theme` holds.
[`tests/test_list_palette.py`](../tests/test_list_palette.py) runs the patchers for real and
fails if any field here disagrees with what they write.

**Determinism note:** the usage map is derived from repo files and is identical on every
machine. The `token → hex` values, the vscode matches and the ΔE distances are read from the
*active* install, so they reflect the current theme. After switching themes,
`python helper/gendocs.py --check` may legitimately report the `PALETTE` block as stale —
regenerate it to match the active theme.
