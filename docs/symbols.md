# Symbols and Strings

What every surface draws when it is not drawing a colour: the icons, the ladders, and the
handful of sentences the desktop says out loud. The block below is generated by
[`helper/list_symbols.py`](../helper/list_symbols.py) — run `python helper/gendocs.py` to
refresh it.

> Three documents cover what a theme sets. **Colour** is
> [palette-semantics.md](palette-semantics.md) and [palette-reference.md](palette-reference.md).
> **Everything else** is this file.

## The Layering

The repository ships the **ASCII** vocabulary in [`helper/symbols.py`](../helper/symbols.py).
A theme bundle overrides what it cares about, through `symbols` and `strings` blocks in its
`config.json`, and `install.py` merges the two into `~/.config/config.json`. Every consumer
reads the merged result, the same way it already reads the merged palette.

```text
helper/symbols.py          ASCII, always renders          "vpn.off": "!vpn"
        ↓ merged by install.py
assets/<name>/config.json  the bundle's overrides         "vpn.off": "󰲝"
        ↓ written to
~/.config/config.json      what every surface reads
```

The defaults are ASCII rather than the glyphs because nothing here asks the font what it can
draw. `setup.toml` states the assumption — *"It must be a Nerd Font — the bar draws glyphs
from the private use area"* — and a machine that breaks it used to get a row of tofu. A
fallback that has to be selected is one nobody selects in time, so it is the default instead,
and the shipped bundle layers the glyphs back on top. Nothing changes visually on a machine
that has the font.

An override is partial: a bundle naming one key keeps the other eighty. That rule predates
the vocabulary — `patch_web_greeter` has relied on it since a login theme could pin its font
size without restating the family — and `tests/test_symbols.py` asserts it.

## Two Shapes of Value

A **string** is one icon or one message. A **tuple** is a ramp: a ladder indexed by a level,
like the battery's eleven rungs or the meter's eight. `helper/symbols.py` records how long
each ramp has to be, because a short one is an `IndexError` inside a widget's `poll()` —
which stops qtile rescheduling that cell for the rest of the session, rather than drawing
something visibly wrong. `tests/test_glyph_ramps.py` checks every ramp, the ASCII defaults
and the shipped bundle's alike, for length, coverage and monotonicity.

Spacing is deliberately not in the vocabulary. Several glyphs need a trailing space because
their ink overruns their advance width; that is a property of the glyph and its renderer, so
the consumer adds it and an ASCII stand-in is not stuck with padding it does not need.

## What Is Deliberately Not Here

- **starship's forty-three distro logos and its per-language icons.** They are starship's
  vocabulary rather than the desktop's, and they would have made this table mostly OS logos.
  Only the four characters the prompt itself draws are here; the rest stay in
  [`starship.toml.template`](../configuration/starship/starship.toml.template), which is the
  file to edit.
- **vim's two airline symbols.** No patcher writes `.vimrc`, and adding one for two glyphs is
  disproportionate.
- **The login screen keeps its own layer.** It had `symbols` and `strings` before the rest of
  the desktop did, and its three-layer fallback — inline HTML, a CSS `var()` default, `||` in
  JavaScript — works when JavaScript never runs, which nothing else here can claim. The
  bundle's vocabulary is written beside each theme as `vocabulary.json` and merged *under*
  its `theme.json`, so a login theme still has the last word and inherits the rest. See
  [THEME-DEVELOPMENT.md](../configuration/web-greeter/THEME-DEVELOPMENT.md).

## After Pulling an Update

A machine installed before this vocabulary existed has a `~/.config/config.json` with no
`symbols` block, so `resolve()` finds no overrides and every surface falls back to ASCII —
correctly, silently, and indefinitely. Refresh it:

```bash
python install.py --migrate
```

That merges the bundle's overrides back over the defaults and re-runs the patchers, keeping
the state this machine is in. Reload qtile afterwards; it reads the configuration at startup.
See [architecture.md](architecture.md) for why this is a separate path from installing.

## Adding an Entry

1. Add the key to `SYMBOLS` or `STRINGS` in [`helper/symbols.py`](../helper/symbols.py), with
   an ASCII value. If it is a ramp, add its length to `RAMP_LENGTHS`.
2. Read it somewhere. `gendocs.py` refuses a commit while a declared key has no consumer — a
   symbol nothing draws is dead vocabulary.
3. Override it in `assets/default/config.json` if the shipped theme should draw a glyph.
4. Run `python helper/gendocs.py` to refresh the block below.

A key read through a namespace rather than by name — the plymouth messages, the login
screen's whole block — needs a row in `list_symbols.NAMESPACE_CONSUMERS`, or step 2 will not
see it.
