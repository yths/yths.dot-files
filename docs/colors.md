# Colors

An overview of how colors are logically mapped across this repo's configurations. The block
below is generated by [`helper/list_colors.py`](../helper/list_colors.py) (run
`python helper/gendocs.py` to refresh it). See [color-semantics.md](color-semantics.md) for
the palette contract and [architecture.md](architecture.md) for how the palette reaches each
app.

It has three parts:

- **Palette** — the semantic `token → hex` table, read from the active `~/.config/config.json`.
- **Role maps** — which token each consumer assigns to which logical role (qtile widgets and
  layouts, web-greeter CSS roles, plymouth assets). This is the palette-driven layer.
- **Drift report** — the tools that hardcode hex *outside* the palette (kitty, tmux, starship,
  dunst, rofi). Each color is reverse-mapped to its nearest palette token so genuine drift is
  visible; an `exact` ΔE means the hardcoded value still matches a palette token.

**Determinism note:** the role maps are derived from repo files and are stable. The `token → hex`
values and the ΔE distances are read from the *active* install, so they reflect the current
theme and will differ per machine. After switching themes, `python helper/gendocs.py --check`
may legitimately report the `COLORS` block as stale — regenerate it to match the active theme.
