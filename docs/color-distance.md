# Colour Distance

How far the two applications whose colours are *resolved* had to move each one. The block
below is generated by [`helper/list_color_distance.py`](../helper/list_color_distance.py) —
run `python helper/gendocs.py` to refresh it.

Most patchers are told which palette token to use: `patch_tmux` writes `highlight` into
`color2` because somebody decided that. Two are not. VSCode and qutebrowser each take a stock
theme of several hundred colours and replace every one with the nearest colour the palette
has, measured in CAM16-UCS — see [palette-reference.md](palette-reference.md) for which token
each key ended up on.

That is only a good idea while *nearest* is actually near. A ΔE of about 2 is the smallest
difference an eye reliably notices; past roughly 20 the replacement is a different colour
rather than a near one. A palette that has drifted, lost a token, or was never meant for a
dense editor theme looks exactly like one that fits — until this is read.

## It Reports, It Does Not Refuse

A large distance says the palette cannot represent that colour. That is a fact about somebody's
design, not a defect in this repository, so `gendocs.py` regenerates this block and never
refuses a commit over it. The numbers are evidence to read when a surface looks wrong.

Two patterns worth knowing how to read:

- **The largest distances cluster on keys where `background` is excluded.** Selection, hover,
  drop, focus, match and range backgrounds may not match the `background` token, because a
  selection painted in the colour it is selecting against is invisible — the defect recorded
  in [issues.md](issues.md). Stock themes make those surfaces a near-background grey, so with
  the one plausible token withheld they land far away. A large ΔE there is the exclusion
  working, not the palette failing.
- **One token absorbing every outlier** is the palette's real gap: the stock theme needs a
  colour in a region the palette has nothing in.

The palette is read from the bundle under `assets/`, not from the active
`~/.config/config.json`, so this block is the same on every machine and changes only when the
bundle does.
